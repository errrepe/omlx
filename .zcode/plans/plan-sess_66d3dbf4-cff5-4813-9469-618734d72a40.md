# Fase H — Autotune de expert-streaming por máquina, salvo como perfil do modelo

**Objetivo:** um tuner offline (`bench/autotune_expert_streaming.py`) que faz buscas de parâmetros para modelos MoE por streaming, com hard-stop de memória (nunca estourar pro swap), ciente de contexto (2k screening + validação 8k), objetivo **balanceado** (TTFT 50% + decode tok/s 50%), e que salva o resultado como **configuração daquele modelo** no mecanismo que o app já usa (`ModelSettingsManager` → `~/.omlx/model_settings.json`).

Reuso do que existe: `bench/resource_sampler.py` (CPU/RSS/disk/GPU/MLX já amostrados), `bench_expert_streaming.py` (trial engine), math de ceiling do `ProcessMemoryEnforcer`, e o fluxo per-model do app (`ModelSettingsManager.set_settings` → `_load_engine` → `convert_model_to_streaming`).

## Etapa 3 — `bench/autotune_expert_streaming.py`

- **Fase 0 — probe da máquina (sem carregar modelo)**: RAM/available/swap base (psutil); metal cap + reserve estático via math do enforcer (probe-only, sem thread); **probe de SSD** no shard do modelo (leitura seq ~2 GB + preads aleatórios no tamanho de expert) → poda o espaço de QD e classifica o disco; runtime est do modelo.
- **Fase 1 — calibração (descartada)**: trial default (budget 0, QD 16) em 2k — aquece page cache do banco e, pelo resource summary, classifica o gargalo (IO-bound: disk alto+GPU baixo no decode → poda knobs de IO; compute-bound → podado o inverso).
- **Fase 2 — screening em 2k, decode 32, coordinate descent** (~9-12 trials): budget {0, 2, 4} (teto limitado por available), QD {8, 16, 32}, PILOT {0/1}, COALESCE {0/1}, RA {0/1}, SEED {0/1}; topk só com `--sweep-topk` (muda qualidade). Cada trial = **subprocesso** (env por trial; estado MLX/IO-pool limpo) com `--out-dir` próprio.
- **Fase 3 — validação**: head-to-head dos 2 melhores combos; vencedor vs default em 8k com decode 96.
- **Fase 4 — score e saída**: score = 0.5·(1/TTFT norm.) + 0.5·(tok/s norm.) − penalidades (swap>0, aborts do guard); `bench/results/autotune/<stamp>/` com JSON por trial + `recommendation.json` (parâmetros vencedores, tabela, sugestão de tier do enforcer) + resumo no terminal.

**Modelo de segurança (o requisito #1):**
1. Preflight por trial: available ≥ runtime_est + reserve + margem; senão o trial é *skipado*, não a sessão.
2. Ceiling por trial = `min(cap_estático, available_no_início − reserve)` (lição F1: nunca capacidade) passado via `--mem-ceiling-gib`.
3. **Watchdog no tuner** (amostra 2s): crescimento de swap > 2 GiB ou available < 5 GiB → SIGKILL no trial, registrado como falha-segura; reserve diminui nos próximos trials.
4. Dreno pós-trial: só lança o próximo quando available volta a ≥ baseline−2 GiB; 2 kills seguidos abortam a sessão.
5. O tuner nunca roda sozinho — você lança; ele é quem torna os futuros benches seguros.
